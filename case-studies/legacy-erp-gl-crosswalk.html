Legacy-to-ERP GL Crosswalk & Parallel-Run Reconciliation

Proving, line by line, where every legacy general-ledger account and dimension lands in Dynamics 365 F&O, starting from full copies of the legacy ledgers in the data lake.

01 Overview

Project overview

An evidence-based crosswalk from the legacy general ledger to Dynamics 365 F&O, built by matching parallel-run transactions one to one, so the finance switchover rested on tested evidence rather than the mapping file alone.

02 Context

Business context

Finance moved from a legacy ledger to Dynamics 365 F&O, and every report built on the old general-ledger accounts and dimensions had to switch over.

03 Problem

Problem statement

Three things made the switchover hard:

  • The official account-mapping file was incomplete.
  • Dynamics 365 F&O stores dimensions inside a segmented ledger-account string, so old fields had no obvious new home.
  • Finance reporting needed complete copies of both legacy ledgers (general insurance and life) in the data lake, and the set of tables to copy kept changing.

04 Architecture

Solution architecture

Legacy ledgers → full dumps to the lake → profiling of both ledgers → 1:1 transaction matching in the parallel-run month → evidence-based account crosswalk and dimension map

06 Implementation

Implementation approach

Before: full legacy-ledger dumps (Azure Data Factory)

One control-table-driven pipeline per ledger, general and life:

  • A control table in Azure SQL lists the tables to dump, and a Lookup reads it at run time.
  • A ForEach builds a dynamic SQL statement per table, with the table name safely escaped, and copies it from SQL Server.
  • Each table lands in ADLS Gen2 as a delimited text file named after the table.
  • Adding or removing a table is a row change in the control table. The dumps were archived once incremental loads took over.

After: read-only profiling and crosswalk on Fabric

  • Kept only the latest version of each F&O journal row.
  • Profiled the account-segment structure, mapping-file coverage and column fill rates.
  • Ran value-overlap tests to find which F&O column carries each legacy field.
  • Matched transactions in the parallel-run month to build a legacy GL to F&O main-account crosswalk. Each row has its match share, the runner-up account and a confidence flag showing whether it agrees with the official mapping file.
  • Built a dimension value map (for example, class of business).

07 Data quality

Data quality and validation

  • Matches only on the same document and the same amount, keeping unique 1:1 pairs only.
  • A confidence flag on every crosswalk row, compared with the official mapping file.
  • Monthly totals compared per account across the two systems.

08 Results

Results and business impact

A GL crosswalk proven line by line, plus a dimension map, so the switchover rested on tested evidence rather than the mapping file alone.

  • Full legacy-ledger history in the lake: the source for the Silver general-ledger tables behind this crosswalk and behind the group client view's premium by client.

Measured impact: not yet quantified. No revenue, time-saving or accuracy figures are claimed. Company names, real figures and internal rules are withheld.
